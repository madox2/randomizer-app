# Randomizer App

Ultimate randomizer mobile/web application built with [Expo](https://expo.dev) (SDK 57),
React Native and TypeScript. It runs on Android and on the web.

## Development

Requirements: Node.js 20+ (22 recommended) and npm.

```sh
npm install
npm start          # Expo dev server (press `a` for Android, `w` for web)
npm run web        # web in the browser
npm run android    # build and run on a connected device / emulator (needs the Android SDK)
npm run typecheck  # TypeScript
npm test           # unit tests
```

## Build the Android app in Expo Cloud (EAS Build)

1. Install the CLI and log in to your Expo account:
   ```sh
   npm install -g eas-cli
   eas login
   ```
2. Link the project to your Expo account (creates `extra.eas.projectId` in `app.json`):
   ```sh
   eas init
   ```
3. Build ([`eas.json`](eas.json) defines the profiles):
   ```sh
   eas build --platform android --profile preview     # installable .apk for testing
   eas build --platform android --profile production  # .aab for Google Play
   ```
   The first build asks to generate a keystore. The app id is `com.randomizerapp`, the same as the
   published app, so to update the existing Play Store listing upload the original upload key
   with `eas credentials` instead of generating a new one.
4. Optionally publish to Google Play: `eas submit --platform android --profile production`.

The build is configured in [`app.json`](app.json). The version is `3.0.0` and `android.versionCode`
is `6` (the previous release used 5). With `autoIncrement` in the production profile EAS manages
the version code remotely.

## Build the Android app locally (prebuild)

The native `android/` project is generated from `app.json` by `expo prebuild` and is not committed.
Requirements: JDK 17+ and the Android SDK (`ANDROID_HOME` set).

```sh
npm install
npx expo prebuild --platform android --clean   # generates ./android

# android/app/build.gradle
# add signingConfigs
        release {
            if (project.hasProperty('MYAPP_UPLOAD_STORE_FILE')) {
                storeFile file(MYAPP_UPLOAD_STORE_FILE)
                storePassword MYAPP_UPLOAD_STORE_PASSWORD
                keyAlias MYAPP_UPLOAD_KEY_ALIAS
                keyPassword MYAPP_UPLOAD_KEY_PASSWORD
            }
        }
# modify in release build types
            signingConfig signingConfigs.release

# copy keystore to android/app/my-release-key.keystore

cd android
./gradlew assembleRelease    # APK: android/app/build/outputs/apk/release/app-release.apk
./gradlew bundleRelease      # AAB: android/app/build/outputs/bundle/release/app-release.aab
```

For a quick debug build on a device/emulator use `npx expo run:android` (add `--variant release`
for a release build).

Release builds generated by prebuild are signed with the debug keystore. For Google Play add your
own keystore to `android/app/build.gradle` (`signingConfigs.release`) or use a config plugin, then
rebuild. The same build can also be done on your machine with the EAS tooling:
`eas build --platform android --profile production --local`.

## Build the web app

```sh
npx expo export --platform web   # static site in ./dist
npx http-server dist             # preview it locally (any static server works)
```

To host it in a sub directory (e.g. GitHub Pages `https://<user>.github.io/randomizer-app/`) set the
base URL when exporting:

```sh
EXPO_BASE_URL=/randomizer-app npx expo export --platform web
```

`public/privacy.html` and `public/terms.html` are copied to the root of the export.

### GitHub Pages deployment

[`.github/workflows/deploy-web.yml`](.github/workflows/deploy-web.yml) builds the web app with the
base URL above and publishes it to GitHub Pages on every push to `master` (it can also be started
manually from the Actions tab). Typecheck and tests must pass first. One-time setup: in the
repository go to Settings > Pages > Build and deployment and set the source to **GitHub Actions**.
